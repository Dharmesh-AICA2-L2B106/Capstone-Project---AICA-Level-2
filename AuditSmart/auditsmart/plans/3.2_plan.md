# Plan – Prompt 3.2 Import and validation

**Inputs:** prompts/3.2_*.md, SPEC §3.2/3.6/3.7, Appendix A (datasets, validation_errors, jobs), Workbook Step 3.2 check (edge_cases.csv must list every expected error).

## Design
- **Upload protocol.** Two ways in:
  - Chunked: `POST /v1/uploads` → `PUT /v1/uploads/{id}/chunks/{n}` (raw bytes, at most UPLOAD_CHUNK_MB each) → `POST /v1/uploads/{id}/complete` (optional sha256).
  - Single request: `POST /v1/datasets` (multipart, streamed to disk in 1 MB blocks).
  - Both are capped at MAX_UPLOAD_MB (500), compute the SHA-256 and return the mapping suggestion.
- **Parse job** (async; eager in tests).
  - Reads CSV or xlsx in chunks of PARSE_CHUNK_ROWS.
  - Maps headers using synonyms plus an optional override.
  - Parses dates (ISO, dd/mm/yyyy, dd-Mon-yyyy, Excel serial) and amounts (commas, brackets, trailing minus, AED prefix).
  - Writes one Parquet file with amounts as decimal128(24,6) and a `parse_issues` column.
- **Validation job.** Checks balance per voucher and in total (tolerance comes from the rules table), blank account, missing mandatory fields and columns, duplicate line_id, unreadable dates and amounts, TRN format, voucher gaps and GL vs TB.
  - Every issue carries a plain-English message, the first 50 row numbers and a "How to fix" line.
  - Any critical issue sets the dataset status to `blocked`.
  - `require_validated_dataset` (409) protects every downstream endpoint (3.3+).
- **Row numbers** are 1-based data rows, matching answer_key.csv `row_no`.
- **Rules.** `seed_data/rules_seed.json` holds a minimal set (balance tolerance, TRN pattern, decimals), all marked pending_verification. The full library comes in 3.8.

## Tests
- edge: every edge_cases row in answer_key is reported with the right severity, the set is exact, and the message format matches the prompt.
- golden: Population totals (B3003/B3004/B3006/B3008/B3009) agree; dummy_gl has only the 5 answer-key TRN warnings; fy2021_2022 is clean.
- unit: hypothesis round-trips for dates and amounts, mapping, xlsx, the signed amount column, tolerance coming from rules, TB comparison.
- api: chunked and multipart uploads, SHA mismatch, size and format limits, missing chunks, mapping override and re-parse, async executor, rows filters, membership 403, job visibility, the downstream guard, logs scrubbed of party names.

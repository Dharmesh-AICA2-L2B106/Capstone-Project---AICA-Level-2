# Prompt 3.8 - Rules Library (plan)

Source: prompts/3.8_rules_library.md, SPEC 3.4, Appendix A (`rule_versions`), Workbook Stage 3.
Run mode: Savio's steering message (plan -> implement -> pytest -> one local commit; defaults from
firm_methodology_v0.2; open points in plans/DECISIONS.md).

## Scope
1. **DB-backed rules service** (`app/services/rules.py`) behind the existing `get_rule(key, on_date)`
   interface (18 call sites unchanged).
   * Store: `rule_versions` (migration 0005 adds `version`, `domain`, `unit`, `source_ref`, `created_at`).
   * `seed_database()` loads `seed_data/rules_seed.json` idempotently (keyed by rule_key+version).
   * Registry = DB rows when enabled (app lifespan / test fixture), else the seed file (pure unit tests).
     In-process cache, invalidated on every write, 30 s TTL for multi-worker deployments.
   * **Exactly one** version: candidates are `approved` (and, while `RULES_ALLOW_PENDING=true`,
     `pending_verification`, D24) versions whose [effective_from, effective_to] covers the date.
     Approved wins; two of the same status -> `RuleConflict`; none -> `RuleNotFound` with a clear message.
2. **Workflow**: `propose()` (new version, status `proposed`), `approve()` (TaxPartner/Admin only,
   mandatory comment >= 10 chars), `reject()`.
   * approve: rejects overlap with any approved version that does not start earlier (or that would
     have to be split); closes the earlier open version (`effective_to = new.from - 1`); a pending
     seed covering the new start is closed or superseded; writes `audit_log` (old/new); marks STALE.
   * **Immutability**: a `before_flush` guard refuses any change to an approved row except closing
     `effective_to` (once, never later than before) and status -> `superseded`; deleting is refused.
   * **STALE marking**: every current Sample, JeRun, InputVatRun whose `rule_versions_used` / `result`
     contains a ref that lost coverage, and whose data period (dataset profile min/max posting date,
     else engagement FY) overlaps the lost range -> `status = "STALE"` + audit_log row.
3. **Seed extension** (all `pending_verification`, values only from repo texts):
   Decision 13/2026 input-VAT verification keys, Decision 17/2026 employee-expense keys, `vat.codes`,
   `trn.pattern`, CT rate/threshold (no URL), `legal_ref.*` (URL only where recorded in the repo).
4. **API** `/v1/rules`: list versions, resolve `?on=`, propose, approve, reject.
5. **AI rule-extraction parser** (`rule_proposals.parse_extraction`): validates the
   rule_extraction_prompt JSON schema and allowed key families. No AI call here (3.9 wires the stub).
6. Workpaper Rules sheet reads source_ref/source_url from the registry.

## Tests
version by date; exactly-one/conflict; pending fallback on/off; overlap rejected; immutability;
approve closes prior + audit_log; STALE marking (in range vs out of range); roles/comment; API;
migration parity; parser schema/allowed keys.

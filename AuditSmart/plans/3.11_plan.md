# 3.11 Background jobs and large files – plan

Prompt: jobs table (id, type, engagement_id, status queued/running/succeeded/failed/cancelled,
progress, started_at, finished_at, error, result_ref); RQ (Redis) worker behind an interface
so Azure queues can replace it; import, validate, je_tests, input_vat_check and large exports
as jobs with progress; paginated row endpoints with filters; 1,000,000-line performance test,
timings in docs/PERFORMANCE.md.

## Existing (3.2)
`jobs` table already has every column (no migration). In-process thread runner with
`submit(type, closure)`; JOB_EAGER for tests.

## Changes
1. `app/services/jobs.py`
   * `JobBackend` protocol: `dispatch(job_id, task, kwargs)` + `run_callable(job_id, fn)`.
     Eager, Thread and RQ backends; `set_backend()` for tests / an Azure adapter (D36).
   * Task registry `@jobs.task(name)`; tasks take `(job_id, **json_kwargs)` so they can run in
     a separate worker process. `run_task` is the RQ entry point and lazy-loads task modules.
   * `submit(closure)` stays for in-process work with live dependencies (FTA monitor) (D37).
   * Co-operative cancel: `cancel()` -> status cancelled; queued jobs are skipped; running
     jobs stop at the next `set_progress` (raises `JobCancelled`). Cancel wins over a late
     finish (D38). Progress is monotonic.
   * `list_jobs` with visibility + filters + pagination.
2. Tasks: parse (import), validate, je_tests, workpaper (large export). input_vat_check is
   registered in 3.12 using the same mechanism.
3. API: `GET /v1/jobs` (filters engagement_id, status, type; offset/limit),
   `POST /v1/jobs/{id}/cancel` (creator, engagement Manager/Partner, or Admin).
   `POST /v1/workpaper?background=true` -> 202 + job_id.
4. Paginated row endpoints: dataset rows gains date_from/date_to, user_id, min_amount filters
   with Parquet predicate push-down; new `GET /v1/je-tests/{id}/flags` (flag, min_score,
   offset/limit) from `je_flags`.
5. Worker: `python -m app.cli worker` (RQ, queue `auditsmart`); `rq` added to requirements.
6. Performance: `scripts/perf_generate.py` (balanced synthetic GL, N lines) and
   `scripts/perf_run.py` (parse -> validate -> JE timings + peak RSS) -> docs/PERFORMANCE.md.
   A 20k-line smoke run is part of pytest; the 1M run is manual (`PERF_LINES=1000000`).

## Tests

Build "AuditSmart", an official internal web application for a UAE audit firm,
covering sampling (ISA 530), journal-entry testing (ISA 240), VAT and input-VAT
checks, evaluation (ISA 450), working papers (ISA 230) and review (ISA 220).
It must work for any audit firm: every user belongs to one firm and sees only that
firm's clients, engagements and rule decisions.
ARCHITECTURE (must follow):
- No audit calculations in the front end. All calls go through src/lib/engine.ts to
  a Python API (VITE_ENGINE_URL). Long operations return a job id: poll /v1/jobs.
- All database/auth access goes through src/lib/data.ts and src/lib/auth.ts so the
  backend can later move from Supabase to Azure PostgreSQL and Microsoft Entra ID.
- Use mock responses until the engine URL is set. Mocks: two firms (Firm A, Firm B).
- AI never calculates; AI text is a draft only.
DESIGN: navy #1F3864, white, accent #2E75B6; Inter; left sidebar; breadcrumbs;
AED 1,234,567.89 right-aligned; dates dd-MMM-yyyy; server-side paginated tables with
sort, filter, CSV/Excel export; status badges; Help panel on every tab (purpose, ISA
reference, 2-line guide); helpful empty states. Header shows the user's firm name
badge (from GET /v1/firm) and role.
ROLES: Admin, Tax Partner, Partner, Manager (Reviewer), Senior/Staff (Preparer).
- Admin with a firm = Firm Admin (users/roles, firm settings). Admin with no firm =
  Platform Admin (registers firms, links clients). Admin NEVER approves rules.
- Tax Partner approves tax rules (domains VAT, INPUT_VAT, CT, TRN, LEGAL_REF); Partner
  approves methodology rules (all other domains). Manager, Partner, Tax Partner may
  propose overrides. Senior/Staff never see approve buttons.
PAGES:
1 Login. 2 Dashboard: my engagements with progress, open exceptions, WPs awaiting
  review, STALE results, rule alerts and calendar items overdue (red after 7 days);
  card "Rules pending verification for your firm" (count from
  GET /v1/firm/rules/review summary.awaiting_firm_approval, links to Partner Review).
3 Engagements + New engagement (client code, client name - never sent to AI,
  emirate, mainland/free zone, FYE, framework IFRS/IFRS for SMEs, materiality,
  performance materiality, trivial threshold, team).
4 Engagement workspace tabs: Data Import (upload with progress, mapping, profile,
  row-level errors, block on critical) | Sampling (method, confidence, TM, expected
  misstatement, key items, seed; shows CF, formula, rationale, top stratum) |
  JE Risk (tests, flags table, risk score, Benford chart, calendar used) | VAT |
  Input VAT | Testing Grid (Yes/No/N/A, audited value, remarks, evidence upload) |
  Evaluation (green/amber/red conclusion) | Observations (Draft with AI, edit,
  mandatory "I have reviewed and edited") | Working Paper (preview, sign-offs,
  download - disabled with explanation if anything is STALE or unreviewed).
  Any result with rules_pending_verification shows an amber "Rules pending
  verification" badge listing rule_versions_used.
5 Review Queue: notes, return, approve; approved WPs locked.
6 Working Calendar. 7 Rules Library. 8 Jobs monitor. 9 Audit Trail.
10 Admin: users/roles, firm methodology settings, tool version. Platform Admin also
  sees Firms (list, Register firm: POST /v1/firms) and Client assignment (link an
  unassigned client: PUT /v1/firms/{firm_id}/clients/{client_id}; 409 = already in
  another firm, show that message).
11 Partner Review (firm rules): table from GET /v1/firm/rules/review, one row per
  rule: rule_key, domain, value and unit used now (effective), effective_from/to,
  status badge, and Source = Shared default (pending) / Adopted by firm / Firm
  override / Engagement override / Proposal open. Filters: date (on), domain, status
  (approved_by_firm, overridden, awaiting_firm_approval, not_effective), engagement
  (engagement_id). Summary counts on top. Row detail: default vs firm vs engagement
  values, open proposals, firm_approval (who, when, comment), source link.
  Actions, each needing a comment (min 10 characters) in a dialog:
  - Approve default for firm: POST /v1/firm/rules/{rule_key}/approve {comment, on}
  - Approve a proposal: same path with {comment, version_id}
  - Override: form (value, unit, effective_from, effective_to, optional engagement,
    source_ref, source_url, comment) -> POST /v1/firm/rules/{rule_key}/override
  - Reject a proposal: POST /v1/firm/rules/{rule_key}/reject {version_id, comment}
  Show Approve/Reject only if the user's role is in the row's approver_roles
  (TaxPartner for tax domains, Partner for methodology); Override for Manager,
  Partner, Tax Partner; others read-only. Never show Approve/Reject to Admin. Firm settings
  panel: toggle "Require approved rules" (require_approved_rules) with mandatory
  comment -> PATCH /v1/firm/settings; show rules_allow_pending and
  pending_rules_resolve from GET /v1/firm. Show engine error text as returned.
STALE: amber banner on any result whose rule or calendar changed, listing what
changed, with Re-run button.
Footer: "Calculations by AuditSmart engine v{version}; AI text is draft and subject
to auditor judgement." Build in steps: layout, auth, engagements first.

ENGINE CONTRACT (use exactly these paths, field names and values in src/lib/engine.ts
and in the mocks; "?" = optional, "q:" = query, {} = body, "->" = response fields):
- Auth: send the user's JWT as "Authorization: Bearer <token>". Supabase tokens carry
  roles in app_metadata.roles (list) or app_metadata.role, and the firm in
  app_metadata.firm_id (never user_metadata). Entra: "roles" and "firm_id" claims.
- Role names exactly: Admin, Partner, Manager, Senior, Staff, TaxPartner.
- Errors: 403 "This engagement belongs to another firm." for another firm's
  engagement; another firm's rules return 404. Show the message, never data.
- Jobs: poll GET /v1/jobs/{job_id} until succeeded, failed or cancelled (statuses
  queued, running, succeeded, failed, cancelled); "progress" drives the bar.
- Values: sampling method mus|random|systematic|stratified|key_items_mus; basis
  debit|credit|signed|absolute; confidence 80|90|95|99; size_formula firm|guide;
  dataset kind GL|TB; calendar exception type EXTRA_HOLIDAY|WORKING_DAY; holiday scope
  FEDERAL|EMIRATE, status confirmed|provisional; watched source type html|pdf; working
  paper kind sample|je_run|input_vat_run; evaluation method mus|ratio; rule status
  pending_verification|proposed|approved|rejected|superseded (pending = amber badge).
- GET /v1/firm -> id,name,require_approved_rules,rules_allow_pending,
  pending_rules_resolve.
- GET /v1/firm/rules/review -> firm,on,engagement_id,summary{approved_by_firm,
  overridden,awaiting_firm_approval,not_effective,total,open_proposals},items[
  {rule_key,domain,unit,review_status,default,firm_approval{approved_by,approved_at,
  comment},firm_override,engagement_override,open_proposals[],effective,
  effective_error,approver_roles[]}]; each rule object: id,ref,rule_key,version,
  domain,value,unit,effective_from,effective_to,status,source_ref,source_url,layer?,
  firm_id?,engagement_id?,firm_approved?.

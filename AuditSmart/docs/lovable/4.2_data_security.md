Create the tables in Appendix A of our spec (below) with row-level security:
- Every user belongs to one firm: auth.jwt()->'app_metadata'->>'firm_id' (never
  user_metadata). Roles: auth.jwt()->'app_metadata'->'roles' (list of Admin, Partner,
  Manager, Senior, Staff, TaxPartner). Put both in SQL helper functions
  current_firm_id() and has_role(text).
- Users see only engagements they belong to AND whose firm_id = current_firm_id();
  clients only of their own firm. Rows of another firm are never visible.
- Manager/Partner approve working papers.
- Rule decisions per firm: Tax Partner approves tax rules (domains VAT, INPUT_VAT, CT,
  TRN, LEGAL_REF), Partner approves methodology rules (other domains), only for their
  own firm; Manager/Partner/Tax Partner may propose firm or engagement overrides
  (engagement overrides: members only). Admin never approves rules.
- Shared default rule_versions (firm_id null) are read-only for all firm users.
- Firm settings (require_approved_rules) editable by Partner, Tax Partner or Admin of
  that firm, with a comment. Platform Admin (Admin with no firm_id) creates firms
  and links unassigned clients to a firm; a client never moves between firms.
- Admin edits federal holidays, emirate profiles, watched sources; Managers/Seniors
  edit work weeks and exceptions for their clients.
- Locked WPs and approved rule versions are read-only; audit_log is insert-only.
Write audit_log on every create/update/delete with old and new values (plus firm_id
and the comment for rule and firm-setting decisions).
Keep all queries inside src/lib/data.ts.

APPENDIX A - Database schema (core tables)
firms (multi-firm) | id text pk, name, require_approved_rules bool default false, created_by, created_at
clients | id, client_code (unique), name, emirate, entity_type, firm_id -> firms (multi-firm; set once, never moved)
engagements | id, client_id, fye, framework, materiality, perf_materiality, trivial, status, firm_id (multi-firm; must equal the client's firm_id, enforced by trigger)
engagement_members | engagement_id, user_id, role
datasets | id, engagement_id, file_name, sha256, rows, total_dr, total_cr, storage_ref, status
validation_errors | dataset_id, severity, field, rows (int[]), message, guidance
samples | id, engagement_id, dataset_id, method, parameters jsonb, cf_value, formula_text, seed, file_hash, rule_versions_used jsonb, engine_version, status (current/STALE), created_by/at
sample_items | id, sample_id, line_ref, book_value, top_stratum bool, attributes jsonb, audited_value, misstatement, remarks, evidence_ref
je_runs | id, engagement_id, dataset_id, parameters jsonb, calendar_hash, rule_versions_used jsonb, engine_version, status
je_flags | je_run_id, line_ref, flags text[], risk_score
input_vat_runs / supplier_register / expense_mapping | per SPEC 3.8
observations | id, sample_item_id, text jsonb, ai_generated, prompt_version, model, reviewed_by, reviewed_at
workpapers | id, engagement_id, wp_ref, status (draft/prepared/reviewed/locked), preparer, reviewer, dates, tool_version
rule_versions | id, rule_key, value jsonb, effective_from, effective_to, source_url, source_doc_hash, status (pending_verification/proposed/approved/rejected/superseded), proposed_by, approved_by, approved_at, comment; firm_id -> firms null = shared default, engagement_id null = firm level, based_on_id -> rule_versions (multi-firm). Constraint: no overlapping approved periods per rule_key within the same firm_id + engagement_id
firm_rule_approvals (multi-firm) | id, firm_id, rule_version_id (a shared default), approved_by, approved_at, comment (not null). Unique (firm_id, rule_version_id)
watched_sources / update_alerts | url, type, active, last_hash, last_checked / source_id, detected_at, summary, proposal_ids, status
holidays | date, name, scope (FEDERAL/EMIRATE), emirate, status (provisional/confirmed)
emirate_profiles | emirate, off_days int[], effective_from, effective_to
company_workweeks | client_id, off_days int[], half_days jsonb {weekday: cutoff}, effective_from, effective_to. Constraint: non-overlapping per client
company_exceptions | client_id, date, type (EXTRA_HOLIDAY/WORKING_DAY), note
jobs | id, type, engagement_id, status, progress, error, result_ref, timestamps
audit_log | id, user_id, firm_id, action, entity, entity_id, old jsonb, new jsonb, at - insert-only
